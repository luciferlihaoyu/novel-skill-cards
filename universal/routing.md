# 通用卡与专精卡路由说明

## 职责划分

- **已有专精卡**：负责单一领域的深度分析、生成或改写，保留其完整流程、脚本和资源。
- **A 系列通用卡**：负责自动写作流程编排、上下文约束、状态闭环与质量门禁，不替代正文生成模块。
- **B 系列通用卡**：负责人工稿件的只读检查和统一报告，不替代需要深度改写或客观测量的专精卡。

同一任务只选择一个主处理卡。通用卡发现需要深度处理的问题时，输出“建议调用的专精卡”，不要同时重复执行两套同类规则。

## 重叠功能路由

| 通用卡 | 相关专精卡 | 默认路由 |
|---|---|---|
| A02 作品圣经管理 | `worldbuilding-bible` | 自动流程中的状态读取与轻量更新用 A02；首次深度构建或重构设定体系用专精卡 |
| A04 长篇结构与分卷规划 | `outline-architect` | 自动流程中的分卷衔接用 A04；完整总纲、章级细纲与三线排期用专精卡 |
| A05 章节任务与场景规划 | `outline-architect`、`chapter-hook-crafter` | 本章任务与状态变化用 A05；完整章纲用前者，章末钩子专项优化用后者 |
| A11 文风与视角偏移检测 | `style-fingerprint` | 自动章节审校用 A11；建立客观文风档案、测量句长与词频用专精卡 |
| B02、B06—B08 连续性核对 | `novel-consistency-checker` | 快速只读核对用 B 系列；全书深度穿帮排查、数值算术和锚点检索用专精卡 |
| B09 章节功能与节奏 | `webnovel-pace-analyzer` | 单章功能与叙事节奏用 B09；逐章爽点信号扫描和连载节奏统计用专精卡 |
| B12 重复冗余与表达 | `deai-rewrite` | 只诊断重复和语言故障用 B12；AI 腔测量与定向改写用专精卡 |
| B14 开篇与作品包装 | `opening-crafter`、`book-packager` | 包装一致性与发布前核对用 B14；开篇结构重做用前者，文案生成用后者 |

## 深度规则归属

以下领域的深度规则以专精卡为维护源，通用卡只保留轻量检查与流程约束：

- 世界观构建：`worldbuilding-bible`。
- 总纲与章纲：`outline-architect`。
- 章末钩子：`chapter-hook-crafter`。
- 客观文风测量：`style-fingerprint`。
- 全书一致性深检：`novel-consistency-checker`。
- 爽点节奏统计：`webnovel-pace-analyzer`。
- AI 腔测量与改写：`deai-rewrite`。
- 开篇结构与包装生成：`opening-crafter`、`book-packager`。

修改上述深度规则时，同步检查通用卡是否仍准确描述路由和轻量检查边界。不要为了“共享文件”破坏独立 Agent Skills 卡可单独安装的特性。

## 调用决策

1. 用户只要单项深度结果：直接调用专精卡。
2. 系统正在自动生成连续章节：使用 A00 调度，必要时请求专精卡产出深度资料。
3. 作者只要求检查自己的稿子：使用 B00 或单张 B 卡，默认不修改正文。
4. 通用卡与专精卡结论冲突：保留双方证据，优先核查正文事实和资料版本，不以卡片级别代替证据。
5. 缺少资料：输出待确认项，不为了完成流程而补造旧文或设定。
