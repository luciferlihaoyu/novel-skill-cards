# 多书横评模式(Syntopical Mode)

> 多书横评 = 以问题为中心同时拆多本书:**书为你服务,不是你为书服务**。不是把 N 份单书拆解复述一遍,而是让几本书回答同一组问题——用同一套语言作答,每个判定附各方章节引证,禁止凭印象下结论。

## 目录
1. 定位与触发
2. 中立词汇表(协议核心)
3. 对比工作流(五步)
4. 规则与防坑
5. 核对横评时必问的问题（Key Questions）

## 1. 定位与触发

**适用场景**:
- 同流派竞品分析:三本起点升级文对打,谁的底层设计更耐读
- 命运对比:题材相近的几本,为什么这本火那本扑
- 作者写法对比:同一作者前后期,或不同作者写同一题材

**不适用**:单书拆解走主工作流(SKILL.md 第 0-5 步),本文件不接单书任务。

**入场条件**(缺一即中断):
- ≥2 本已完成**同目的**拆解的书,各有 `《书名》拆书报告.md` 落盘
- 或用户同批上传多本并明确要求对比

报告缺失,或各书拆解目的不一致(一本仿写向、一本诊断向)→ 中断:先按主工作流逐书拆完、口径拉齐,再来横评。

## 2. 中立词汇表(协议核心)

各书各说一套:"金手指/系统/外挂","爽点/情绪包/期待感"——名词不统一,对比就是各说各话。开工前先建中立词汇表,强迫每本书用同一套语言答题:

| 中立术语 | 《A 书》的说法 | 《B 书》的说法 | 判定是否同物 |
|---|---|---|---|
| 金手指 | "系统"(第3章发放) | "神级天赋"(第1章觉醒) | ✅同物:均为主角独享的超常助力,归并 |
| 升级 | "境界突破"(数值阶梯) | "血脉进化"(规则改写) | ❌不同物:规则结构不同,不得混比 |

- **同物不同名**:必须归并到同一中立术语下
- **不同物同名**:不得混比——都叫"升级"但规则结构不同,就不是同一个东西
- **词表先于矩阵**:中立术语未定稿,任何对比表格不得开填;词表定稿后作为报告附录
- **一句话检验**:横评报告读完后,用户带走的是"问题的答案",不是"每本书说了什么"——两者都给,但前者是主角

## 3. 对比工作流(五步)

### 第 1 步:单书报告就位

逐本核对 `《书名》拆书报告.md`:记下存放路径与页内小节号,后文一律用"(见《书名》报告 §6.3)"式回指。任一本不存在 → 中断并说明:先跑单书流程,拆完再来横评。单书报告未过交叉核对(见 SKILL.md 第 3 步)的,先补核——单书的矛盾数据会直接污染对比矩阵。

### 第 2 步:建中立词汇表

按第 2 节执行,产出词表定稿。

### 第 3 步:逐维度头对头(对比矩阵)

先问用户要什么答案(如"同题材为什么 B 扑了"),再从五维度(黄金三章/情节/人物/世界观/商业要素)中挑 3-5 个承载该问题的维度。**行是对比项,列是书**,每个单元格 = 该书在该维度的结论 + (第X章) 引证:

| 对比项(维度:商业要素·金手指,见 webnovel-elements.md §3) | 《A 书》 | 《B 书》 | 《C 书》 |
|---|---|---|---|
| 金手指限制与代价 | 每次动用折寿一天,可感知可累积(第38章;第120章主角因代价弃用) | 未设限制(其报告 §6.3 明写"未设定限制") | 证据不足(报告 §6.3 标注未覆盖;第89章疑似有代价暗示,判定降权) |
| 长线伏笔是否回收 | 主线悬念第12章埋、第340章收(✅已回收) | 头号长线伏笔❌未回收(其报告 §3.5 台账) | 该书未涉及(报告 §3.5 明写"全书无长线伏笔") |

对比项的判定口径沿用各维度文件,本文件不重定义:情节看节奏与伏笔(见 plot-structure.md §4、§5),人物看关系网(见 character-system.md §4),设定看力量体系(见 worldview-timeline.md §2),开篇看钩子(见 golden-three-chapters.md §2)。

### 第 4 步:逐项判定

每个对比项出一条判定,只回答两问:
- **谁做得出色,可迁移技巧是什么**?
- **谁踩了坑,教训是什么**?

判定必须两侧(或多侧)都有原文引证。示例:

> 金手指限制:✅《A》胜出——代价明码标价、随用随扣(第38章),主角因代价主动弃用(第120章);❌《B》无代价设定,后期以"副作用"补救生硬(第210章)。可迁移:A 的"明码标价"让读者能预判主角的下一步。

禁止"显然 A 更好"式无据压价;同一对比项允许各侧各有胜负——《B》的期待感装置(见 webnovel-elements.md §2)可以比《A》密,两项判定互不抵消。

### 第 5 步:产出横比报告

输出 `《A vs B vs C》横比拆书报告.md`(落盘为文件,同 SKILL.md 第 4 步要求),结构:
1. **对比矩阵**——第 3 步产出
2. **逐项判定**——第 4 步产出
3. **附录:中立词汇表**——第 2 步定稿
4. **可执行结论**:"若你是 B 书作者,可偷的三招"——每招注明偷自哪本书哪个章节,禁止空泛口号
5. **限制声明**:集中列出各单书报告的"未覆盖"声明与本次矩阵的"证据不足"格——横评报告必须带着自己的边界交付

## 4. 规则与防坑

- **只比可学习差异**:对比围绕"能学什么"展开,不做整体打星排名;单书评分量表(见 golden-three-chapters.md §5)只在单书内部有效,不得跨书折算总分。用户明确要求排名才做,且每个名次仍须附引证
- **判定禁悬空**:一条判定成立须同时满足 (a) 同维度 (b) 同场景类型(A 的拍卖会对 B 的宗门大比属场景错位,先标注再比) (c) 双侧引证齐全
- **缺则明示**:某书没有的内容写"该书未涉及",不做脑补平衡——禁止为了表格好看替书编内容
- ⚠️ **横评效力 ≤ 单书质量**:横评结论的效力取决于单书拆解质量。单书报告带"未覆盖"声明的维度,对比矩阵必须继承该限制:该格标"证据不足",不得硬比
- **两个标签的分工**:"该书未涉及" = 单书报告明写主题缺失(如"全书无长线伏笔"),该格不参与判定;"证据不足" = 单书报告未覆盖、仅有疑似线索,该格保留疑似结论并在判定中降权;连疑似线索都没有的,同样不参与判定

## 核对横评时必问的问题（Key Questions）
1. 每个对比项是否同维度、同场景类型?场景错位(如 A 的拍卖会对 B 的宗门大比)是否已先标注再比?
2. 中立词汇表是否在矩阵开填前定稿?同物不同名是否全部归并,不同物同名是否都标了"❌不得混比"?
3. 每个参与判定的单元格是否双侧(或多侧)引证齐全,(第X章)与(见《书名》报告 §N)是否必居其一?
4. 单书报告的"未覆盖"声明是否已继承成标签——明写主题缺失的标"该书未涉及",未覆盖仅疑似的标"证据不足"并降权?
5. 每条判定是否只答"谁做得出色+可迁移技巧 / 谁踩坑+教训"两问,无"显然 A 更好"式无据压价?

## 警示信号（Warning signals）
- 中立词汇表未定稿就开填对比矩阵（见上文 §2）
- 对比项从五维度里凑数,与用户的问题清单脱钩（见上文 §3）
- 某单元格无引证仍参与判定,或只有单侧引证就下"谁更出色"（见上文 §3）
- 判定出现"显然 A 更好"式无据压价（见上文 §3）
- 拿 A 的标准直接压 B 的内容,或不标注场景错位就跨场景硬比（见上文 §4）
- 单书报告带"未覆盖"声明,矩阵却照常硬比,未标"证据不足"（见上文 §4）
- 不同物同名(都叫"升级")没标"❌不得混比"就进了同一行（见上文 §2）
- 用户未要求仍输出整体打星排名,或名次不带引证（见上文 §4）
- 横比报告沦为逐书摘要复读,用户的问题没有正面答案（见上文 §2）

## Agent 硬指令（Agent instruction）
1. 核对入场券:开工前逐本确认 `《书名》拆书报告.md` 存在且带章节引证;缺一本即中断,回复"先按主工作流逐书拆完再横评"。
2. 建立中立词汇表并冻结:同物不同名一律归并,不同物同名一律标"❌不得混比";词表未定稿禁止填矩阵。
3. 给每个矩阵单元格挂引证:(第X章)或(见《书名》报告 §N)二者必有其一;都拿不出就写"证据不足",该格不参与判定。
4. 给每条判定双侧留证:说《A》出色必须同时引《B》原文并指出其教训;除非用户明确要求,禁止输出整体打星排名。
