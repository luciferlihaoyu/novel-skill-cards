# 拆书(Novel Deconstruction)

把一部网文/小说拆解为可学习、可复用的结构化报告。核心目的:**搞清楚这本书为什么这样写、为什么火(或不火)、能学什么**。

## 分析维度速查

| 用户问的是 | 加载参考文件 |
|---|---|
| 开篇、前三章、黄金三章、开头吸引不吸引人 | `references/golden-three-chapters.md` |
| 情节、脉络、主线、走向、节奏、伏笔、套路 | `references/plot-structure.md` |
| 人物、人设、角色、关系、反派 | `references/character-system.md` |
| 背景、世界观、设定、等级体系、时间线 | `references/worldview-timeline.md` |
| 爽点、期待感、金手指、为什么火、平台适配 | `references/webnovel-elements.md` |
| 全书完整拆书 | 全部加载 + `assets/report-template.md` |
| 多本同流派对比/竞品对打/A vs B 横评 | `references/syntopical-mode.md` |

> 注意:`references/consistency-check.md` 不属于可选维度——任何任务在第 3 步都必须加载执行。
>
> 多书对比路由 `syntopical-mode.md` 的先决条件:对比前提是各书已各有单书拆解报告,未拆过的书先走单书拆书流程。

## 工作流

### 第 0 步:明确拆书目的与范围

先确认(用户没说就问,一句带过):
- **目的**:学习仿写(侧重技巧清单)/ 竞品分析(侧重商业要素)/ 改稿诊断(侧重问题清单)
- **范围**:全书 / 前 N 章 / 黄金三章 / 指定维度

只问黄金三章时,不要强行做全书分析;用户给的范围就是交付范围。

### 第 0.5 步:拆解预判(检视报告门禁)

切章统计(第 1 步产出)出来后、深度分析开始前,先产出 **≤400 字的"拆解预判"**给用户:
- **类型判断**:流派与平台适配初判
- **题材密度与创新度初评**:题材元素浓度与同类书对比下的新鲜度
- **主要风险**:水文段/断章/烂尾嫌疑
- **建议拆解深度**:全书级完整拆解 / 黄金三章+情节+商业要素即可 / 该书核心套路在桥段,建议主题式拆解

给出**明确建议 + 用户确认**再展开全量分析。跳过条件:用户已明确指定范围(如"只拆前三章"),或使用一键式指令(如"直接全书拆,别再问我")时,本步可跳过。

> 本步与"只问黄金三章时不做全书分析"同一精神:预判在前,把成本选择权交给用户,避免默认对百万字白拆一遍。

### 第 1 步:文本预处理

小说动辄百万字,**必须先切分**:

```bash
python scripts/chapter_splitter.py <小说文件> --out-dir <工作目录>
```

- 产出 `chapter_index.json`(章节号/标题/字数)和单章文件
- 全书统计(总字数、章节数、前三章字数)写入报告"总览"
- 无法识别章节标题时脚本自动按字数切块,报告中注明"按字数块分析"

支持格式:txt 直接用;docx/pdf 先用对应工具转为文本再切分。

### 第 2 步:分维度分析

按"分析维度速查"加载对应 reference 文件,严格按其中的清单和表格执行。

**阅读量规则**(防止浅尝辄止):
- 黄金三章分析:精读前 3 章全文
- 情节/人物分析:至少覆盖每卷开头 + 高潮章 + 卷末;长篇按比例抽样并注明抽样率
- 时间线分析:依赖章节索引 + 时间词检索,逐章扫读时间锚点
- 所有结论必须标注章节依据(第X章),禁止无依据的泛泛而谈

**长篇策略**(>100 章):若运行环境支持多代理并行,可按卷/按维度分配并行分析(每个代理分配章节范围 + 指定 reference)后汇总;否则按"每卷开头/高潮/卷末"抽样。

**成本中途确认**(全书拆解且章节 >50 时):开工前向用户报"预计分析 N 章、各维度报告总量约 X 字",并给出抽样方案选项(每卷开头+高潮+卷末抽样 / 多代理按卷并行 / 指定范围);**未获确认不得默认展开**。

**单章不整读**:>6000 字的单章按"检查维度所需的段落扫描"处理,不做逐字通读;全书超大时优先靠 `chapter_index.json` 定位,不整体读入。

### 第 3 步:交叉核对(强制,任何范围)

分维度表格填完后、写报告前,加载 `references/consistency-check.md` 做一次跨表一致性核对:

1. 先运行 `python scripts/fact_extractor.py <工作目录>` 加载 `facts_index.json` 作"事实清单"雏形,再人工补漏;如无索引,仍把可证伪的事实收拢成清单(每条带章节+原文):数值规则与每次结算、文中声称的累计量、时间词与时长、物品/能力的获得方式、人物的生死与下落;
2. 再做三层核对——**数值算术**(规则×时间/次数 ≠ 文中声称结果)、**设定口径**(同一事物出现两种说法)、**细节连续**(同一事件/物体的描述前后变化);
3. 每条矛盾给**双侧章节+原文引证**、严重度和修改建议,写入报告"文本矛盾清单";核对后无矛盾也必须写明"已核对,未发现"。

穿帮的高发原因不是没读到,而是两个事实分别记进了不同表格、从没碰过面——这一步就是让它们碰面。

### 第 4 步:输出报告

- 全书拆书:复制 `assets/report-template.md` 逐项填写,输出为 Markdown 文件,保存到当前工作环境的输出目录,命名 `《书名》拆书报告.md`
- 单维度分析(如只问黄金三章):按对应 reference 末尾的"输出要求"组织,可直接回复,长报告仍写文件
- 报告为长文交付物,必须落盘为文件,不要只发在对话里

### 第 5 步:总结三件套(每份报告必须有)

1. **这本书为什么火(或不火)** —— 3-5 条核心结论
2. **可学习的技巧清单** —— 每条注明出处章节
3. **避坑清单** —— 该书暴露的问题

## 质量标准

- **有据可查**:每个判断附章节引用;没有读到的部分明确说"未覆盖"
- **拆书不是复述**:价值在于"为什么这样写"和"效果如何",不是章节内容摘要
- **网文视角**:除文学性外,必须关注爽点/期待感/留存设计等商业要素(见 webnovel-elements.md)
- **诚实标注**:未回收伏笔、设定矛盾、水文段落要直接指出,不做无脑吹捧
- **理论不教条**:黄金三章等是经验法则而非铁律,分析时允许"打破规则但自洽"的正面案例
- **发现归位,只写一次**:同一结论放在最相关的一节,他处用"(见 X.X)"引用,禁止跨节复读
- **报告无过程信息**:交付物面向读者,不出现技能名、reference/脚本名等元信息(样本覆盖范围说明除外)
- **负面结论四分类**:所有对本书/作者的负面判定必须归类——(a) 事实性穿帮(数值/口径/连续性矛盾,由第 3 步矛盾清单覆盖)、(b) 人设失当(如反派降智、主角工具化)、(c) 不合逻辑(情节因果不成立/为反转而反转)、(d) 分析不完整(该指出的技法问题未指出;此项仅用于自检拆书遗漏,不作为评价本书的标准)——每条标注 (a)-(d) 之一并附章节证据,禁止悬空写"感觉有点拉"

## 常见失败模式(避免)

- ❌ 只读前 10 章就对全书下结论 → 注明覆盖范围,或按抽样策略扩大阅读
- ❌ 报告变成逐章剧情梗概 → 梗概限 500 字内,其余篇幅给分析与评价
- ❌ 堆砌术语无实例 → 每个术语判断配一个书中实例
- ❌ 忽略用户目的 → 仿写目的多给技巧清单,诊断目的多给问题清单
- ❌ 负面结论不归类、只给情绪化断言 → 按"负面结论四分类"标注类别并附章节证据
