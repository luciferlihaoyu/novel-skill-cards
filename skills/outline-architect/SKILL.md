# 大纲架构师

网文大纲不是故事梗概，而是一张**施工图纸**：它必须同时回答"每章写什么"和"读者为什么继续看"。本技能按"三线合一"构建大纲——主线情节负责"发生了什么"，升级线负责"主角在变强/在变"的可视化进度，伏笔台账负责"埋了什么时候收"。

## 工作流程

### 第 1 步：锁定地基（不清楚就一句带过地问）

- **一句话卖点**：这本书最勾人的那个"如果……会怎样"
- **目标体量与平台**：总字数预期 + 目标平台（免费/付费决定节奏密度）
- **主角起点与终点**：开局状态 → 终局状态（升级线的两端）
- **金手指/核心引擎**：主角靠什么赢——它必须可重复使用、可升级、有代价

### 第 2 步：三线设计

加载 `references/outline-framework.md`，依次搭建：

1. **主线情节线**：按卷划分。每卷 = 一个大目标 + 一个大反派/障碍 + 一个卷末大爽点。卷与卷之间必须有"目标升级"（打更大的boss、进更大的地图），不是同类任务重复
2. **升级线**：把力量体系切成若干台阶，标注每个台阶在**第几卷第几章**达成，以及达成代价。升级点必须与情节事件绑定（靠战斗/奇遇突破），不许"闭关三章就升级"
3. **伏笔台账**：每条伏笔登记"埋设位置—计划回收位置—跨度"，跨度超 100 章的必须在中途安排"提醒点"（再次提及，防止读者遗忘、防止自己遗忘）

### 第 3 步：章级细纲（按用户需求决定深度）

把每卷展开为章级细纲，每章一行：

```
第N章 | 功能(铺垫/小爽/大爽/过渡/日常) | 内容一句话 | 字数预算 | 章末钩子类型
```

排期硬规则（按框架文件的平台参数执行）：

- 免费平台：每 1-2 章一个小爽点，每 8-12 章一个大爽点，每章有钩
- 付费平台：每 3-5 章一个小爽点，卷末必须大爽点
- **压抑段**：主角受挫的连续章节不得超过警戒线，且压抑结束前必须让读者看到"翻盘的筹码"
- 细纲写完后用节奏规则自查一遍：标出所有"连续 3 章无爽点"的区间，能重排就重排

### 第 4 步：交付

- 输出 Markdown 文件：一句话卖点 + 三卷式总览（或按卷数）+ 三线表 + 章级细纲 + 伏笔台账
- 明确标注：**大纲是图纸不是镣铐**，写作中偏离时优先更新台账而非硬改正文

## 质量标准

- 每卷的大爽点必须能被一句话说清"爽在哪"，说不清就是没设计出来
- 升级线相邻台阶的难度必须递增，且每级能力边界明确（为 consistency-checker 的事后核对留下可证伪的规则）
- 伏笔台账里不允许出现"以后再说"的回收计划——要么有章节坐标，要么标注"待排期"并集中列在文末
- 细纲只写"这章发生什么+什么功能"，不写对话和描写，那是正文的事
