# 爽点节奏分析仪

网文的本质是**期待感管理**：铺垫制造期待，爽点兑现期待，钩子延续期待。本技能把这件事量化——先用脚本扫出每章的客观指标，再由你结合文本做诊断，避免"凭感觉说节奏不好"。

## 工作流程

### 第 1 步：切分 + 扫描

若尚未切分章节，先切分（可用 novel-consistency-checker 的 chapter_splitter.py，或任何等效方式），然后：

```bash
python {baseDir}/scripts/pace_scan.py <工作目录> --out pace_report.csv
```

脚本对每章输出：字数、章末钩子信号（问句/惊呼/危机词收尾）、爽点信号计数（打脸/突破/收获/揭秘/震惊类关键词）、对话占比。**脚本只提供线索坐标，定性判断必须回到原文**——关键词命中不等于爽点成立（可能只是日常对话里出现"震惊"）。

### 第 2 步：逐章定性

对扫描结果中"连续无信号"的区间重点回读原文，按 `references/pacing-framework.md` 的框架给每章标注：

- **本章功能**：铺垫 / 升级（小爽）/ 高潮（大爽）/ 过渡 / 日常
- **爽点类型**：打脸、实力提升、收获宝物、身份揭露、情感进展、危机解除……没有则标"无"
- **章末钩子**：危机型 / 悬念型 / 揭秘型 / 期待型 / 无（平收）
- **期待账簿**：本章欠下了什么期待、兑现了什么期待

### 第 3 步：诊断输出

基于逐章标注给出诊断，每条结论必须带章节号：

1. **节奏曲线**：按 5-10 章一段概括情绪走向（哪里平、哪里密）
2. **问题清单**：
   - 爽点荒：连续 N 章无爽点（一般以 3-5 章为警戒线，视平台而定）
   - 铺垫过长：铺垫段超过高潮所需，读者耐心耗尽
   - 高潮泄气：大爽点一章写完没写透，或被下一章开头立刻消解
   - 平收尾：连续多章章末无钩子
   - 水文区：过渡章连续出现且信息密度低
3. **修改建议**：具体到"第 X 章结尾改断在 XX 处""把第 X 章与第 X 章合并""在第 X 章提前引爆爽点"

## 质量标准

- 区分**平台语境**：免费平台（番茄类）对爽点密度要求高于付费平台（起点类），诊断前确认目标平台，未知则按免费平台标准并注明
- 不以密度论英雄：日常章、情感章可以是有效章节，判"水"的标准是**既不推进期待也不兑现期待**
- 黄金三章单独评价：开篇是否快速立住主角与金手指、第一章末是否有钩子、三章内是否出现第一个爽点
- 报告给坐标和方案，不替作者重写正文
